# owner-contracts — 투입 요청과 호기 배정

## 목적 · 역할
소유주가 건설사의 투입 요청을 받아 **"이 기간에 낼 수 있는 장비가 있나"** 하나를 판단하고, 호기를 배정해 회신한다. 시안 «소유주 업무 기획» «확정 2026-09-12»가 정한 흐름을 실현한다: 요청 접수 → 투입 가능 장비 확인 → 호기 배정·기간 확정 → 운송·설치 → 가동 → 종료·회수. 배정 확정은 이 데모 안에서 계약 기간을 채우고 보유 장비·운영 현황에 반영되며, 실제 계약 체결·비용·재고 연계는 범위 밖이다(DISC-052).

## 수용 기준
- **AC-1** Given 상태가 섞인 요청 5건 When 요청 목록 → 상태(요청 접수 · 배정 중 · 운송·설치 · 가동 · 종료)별로 묶여 보이고 각 건에 현장 · 건설사 · 안전관리자 · 희망 기간 · 필요 대수 · 사양이 남는다 Then 목록만으로 어느 건을 먼저 볼지 정할 수 있다. [FR-026]
- **AC-2** Given 필요 대수 3인 요청 When 배정 화면 → 후보 호기는 **보관 중 + 계약 종료 임박**에서만 나오고, 각 후보에 가용 근거(보관 위치 또는 종료일)와 확인 사항이 붙는다 Then 소유주가 근거를 보고 고를 수 있다. [FR-026, FR-025, FR-043]
- **AC-3** Given 후보를 N/N 채운 상태 When «배정 확정·회신» → 그 호기들의 계약 기간이 요청 기간으로 채워지고 요청은 다음 상태로 넘어가며 보유 장비·운영 현황에 같은 사실이 보인다 Then 한 곳의 확정이 세 화면에서 같게 읽힌다. [FR-026, FR-025]
- **AC-4** Given 요청 기간에 낼 수 있는 호기가 없는 요청 When 배정 화면 → 후보 0건과 그 이유(보관 0 · 종료 임박 0)를 문장으로 보이고 확정 버튼은 비활성이다 Then 빈 결과를 «없음»이 아니라 원인으로 읽는다. [FR-026]
- **AC-5** Given 다른 소유주의 요청·호기 When 같은 URL 직접 접근 → 조회되지 않는다(ownerId 누락·공백도 거부) Then 테넌시 경계가 요청 축에도 적용된다. [FR-024]

## 상태 픽스처
`inbox` 상태별 5건 · `assign` 후보 3/3 채움 직전 · `empty` 대기 요청 0 · `none` 후보 0 · `error` 조회 실패 후 재시도. capture 모드에서만 적용한다.

## 비범위
실제 계약 체결·전자서명 · 비용·정산 · 재고 연계 · 운송 일정 관리 · 요청이 앱으로 직접 들어오는 경로(전화·메일 접수 기록인지 미결 — DISC-052). 서류 승인 권한은 주지 않는다.
