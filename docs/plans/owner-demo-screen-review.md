## 1. 검토 결론

**운영 현황 · 보유 장비 목록 · 호기 상세 · 영상 보기 · 장비 서류 · 이상·점검 알림의 6개 화면 구성이 적절하다.** 메뉴는 운영 현황·보유 장비·알림·서류 4개로 묶는다. 상세와 영상은 장비를 선택해 들어가는 화면이다. 6개라는 수와 메뉴 구성은 V5의 기능을 설명하기 위한 설계 제안이며, 고객 원문에 정해진 화면 수는 아니다.

**현재 구현은 소유주 고객이 혼자 둘러보는 데모로 제공하기 전에 보완이 필요하다.** 지도·장비 상태·영상 플레이어·서류 목록은 재사용할 수 있다. 다만 전체 장비를 찾는 목록, 계약·담당자까지 연결되는 상세, 소유주의 서류 열람·첨부, 휴대폰 화면이 충분히 갖춰지지 않았다. 영상의 용도와 보존 표기도 V5에 맞춰야 한다.

**디자인도 구조부터 보완해야 한다.** 반복되는 KPI·표·우측 설명 패널이 지도·영상·문서의 면적을 줄이고 있다. KPI는 보유 규모·투입/보관 구성·확인할 장비로 나누고, 화면별 주인공을 달리한다. 구체적인 진단·시안·개선 순서는 [소유주 데모 디자인 리뷰](../design/OWNER-DEMO-DESIGN-REVIEW-2026-09-11.md)에 정리했다.

**데모 문서의 로그인 장은 ‘소유주 데모 시작’으로 교체한다.** 소유주용 설명·장비 미리보기·단일 ‘데모 시작하기’ 버튼을 사용한다. 문서는 공통 진입 1장 + 업무 화면 6장 = 7장으로 구성한다. 현재 6역할 선택 UI는 개선 전 증거로만 사용한다.

**소유주 모의 검토 반영:** 전체 장비 찾기 → 계약·담당자 확인, 현재/마지막 수신 정보 구별, 장비 서류 원문 열람을 구현 우선순위로 둔다. 지도 면적과 영상 우선 행동은 고정하지 않는다. [의견·반영 판단](../design/OWNER-PERSONA-FEEDBACK-2026-09-11.md)은 실제 고객 인터뷰 결과와 구분한다.

이번 산출물은 화면 정의와 평가다. 제품 코드·SSOT·정식 spec·계약 범위는 변경하지 않았다. 고객 전달이나 데모 배포도 수행하지 않았다.

## 4. 제안 화면 정의

### ① 운영 현황

**사용자의 질문:** 우리 장비가 어디에 있고, 지금 먼저 확인할 장비는 무엇인가?

- 첫 화면: 전체 보유 대수와 투입/보관의 구성 막대, 전국 지도, 먼저 확인할 장비. 네 숫자를 동일한 KPI 카드로 반복하지 않는다. 이상은 투입/보관과 다른 상태 축으로 표시한다.
- 지도 마커와 요약 숫자는 보유 장비 목록의 같은 레코드에서 계산한다.
- 지도에서 호기를 선택하면 요약이 뜨고, 상세 보기로 이동한다. 숫자를 누르면 해당 조건의 목록으로 이동한다.
- PC는 첫 화면에서 호기/현장 검색·전체 목록에 접근하고 지도와 우선 알림을 함께 확인한다. 지도 비율은 고정하지 않는다. 휴대폰은 검색·숫자 요약·알림을 먼저 배치하고 지도를 접을 수 있게 한다.
- 알림 일부만 보여줄 때는 전체 영향 장비 수·현재 표시 수·전체 보기를 함께 제시한다.
- 샘플 5대를 보여주면서 보유 100대라고 표시하지 않는다. V5의 100대/120대 사례는 규모 설명과 대량 목록 검토의 근거다.
- **보완 원칙:** 정상 통신 수신 대수와 실제 가동 대수를 구분한다. 가동률을 넣을 경우 산식·시간 범위를 함께 정의한다.

### ② 보유 장비 목록

**사용자의 질문:** 특정 호기 또는 특정 건설사 현장에 있는 장비를 어떻게 찾는가?

- 전체 보유 장비를 보여주고 호기·현장명으로 검색한다. 건설사·운영 상태로 필터링한다.
- PC 기본 열: 호기, 현장/건설사, 투입·보관 상태, 확인할 상태, 계약 종료일. 설치 일정·계약 전체 기간·마지막 수신은 상세와 필요한 보조 열에서 확인한다.
- 휴대폰에서는 호기·현장·상태를 카드의 첫 줄에, 일정·계약은 보조 정보로 배치한다.
- 행 또는 카드 선택 → 호기 상세. 뒤로 돌아오면 검색·필터·목록 위치를 유지한다.
- 검색 결과 없음, 보유 장비 없음, 조회 실패를 각각 표시한다.
- **보완 원칙:** 운영 현황의 이상 장비 표와 목적을 구분한다. 정상 장비와 보관 장비도 찾아야 한다.

### ③ 호기 상세

**사용자의 질문:** 이 장비가 어느 현장에서 누구 책임으로 운영되고 있으며, 무엇이 문제인가?

- 상단: 호기, 현장·건설사, 계약 기간·담당자, 투입·보관 상태, 마지막 수신 시각. 계약·담당자가 영상 아래로 밀리지 않게 한다.
- 기본정보: 위치, 설치 일정, 계약 시작·종료일. 담당자 연락 정보는 샘플로 표시한다.
- 상태: 통신, 공급 전압, 3상 연결 이상, 단선, 고장코드. 값이 없으면 미연동·미수신을 구분한다.
- 점검 정보: 수송관·필터 상태, 점검에 쓰이는 누적량 또는 시간과 적용 기준.
- 영상 보기·장비 서류·해당 호기 알림으로 이동한다. 선택 호기는 모든 화면에서 유지한다.
- **보완 원칙:** 좁은 PC·휴대폰에서도 상세를 열 수 있어야 한다. 우측 패널을 숨기는 것만으로 반응형을 처리하지 않는다.

### ④ 영상 보기

**사용자의 질문:** 해당 장비의 타설·설치 작업 상황을 지금 또는 저장된 영상으로 확인할 수 있는가?

- 선택 장비와 현장을 고정 표시하고 실시간/저장 영상 탭을 제공한다.
- 실시간: 타설 위치·마스트 설치 채널 중 하나를 선택해 크게 표시한다. 연계된 바디캠은 작업 영상 예시로 제시한다.
- 안전 감지용 카메라는 V5의 경고 용도로 설명한다. 원격 장비 제어 버튼은 두지 않는다.
- 저장: 데모에서 선택한 가동일의 저장 구간·시각·길이를 표시하고 재생한다. 저장분 없음과 아직 확보되지 않은 구간을 구분한다.
- 연결 끊김·마지막 수신 시각·녹화 상태를 표시한다. 대체 영상은 재생 영역에 시연용임을 명시한다.
- **보완 원칙:** 사용자에게는 용도와 시각이 우선이다. 서버/SD/NVR 선택이 사용 판단에 필요할 때만 보조 정보로 제공한다.
- **확인 필요:** “가동 1일분”이 최근 가동일 보존인지 누적 가동시간 기준인지, 삭제 시점은 언제인지 V5만으로 확정하지 않는다. 데모의 하루 구간 예시와 실제 보존 정책은 구분한다.

### ⑤ 장비 서류

**사용자의 질문:** 안전관리자가 요구한 해당 호기의 서류를 바로 찾아 보여줄 수 있는가?

- 첫 목록은 제작증·비파괴 검사 성적서 등 장비 서류에 집중한다.
- 호기·현장·서류 종류로 찾고 문서명, 대상 호기, 등록일, 유효기간이 있는 경우 만료일을 표시한다.
- 목록 → 파일 미리보기 → 닫고 같은 목록으로 복귀하는 흐름을 제공한다.
- 첨부는 데모용 파일 선택·미리보기·목록 반영까지 제안한다. 실제 저장 정책과 등록 권한은 정식 spec에서 정리한다.
- 파일 없음·읽기 실패·첨부 중·실패 상태를 제공한다.
- **보완 원칙:** 운전자 근로계약서·교육 이수증 승인 업무가 장비 서류 탐색보다 먼저 나오지 않게 한다.
- **디자인:** 대표 완비율 KPI보다 문서 찾기와 원문 미리보기를 우선한다. 문서명 → 호기·현장 → 등록일/유효기간 순으로 표시한다. 필수 서류의 분모가 정의되기 전에는 평균 완비율을 대표 지표로 쓰지 않는다.

### ⑥ 이상·점검 알림

**사용자의 질문:** 어느 호기에 어떤 이상이 발생했고, 지금 어떤 정보를 확인해야 하는가?

- 호기·현장·종류·발생 시각·중요도·확인 상태를 표시한다. 샘플 중요도와 임계는 확정 규칙으로 제시하지 않는다.
- 고장/전압/단선/3상 연결 오류와 수송관/필터 점검 알림을 구분한다.
- 항목 선택 → 해당 알림 상세 → 같은 호기의 상태 또는 영상으로 이동한다.
- 알림 읽음과 실제 정비 완료를 구분한다. 읽었다는 이유로 장비를 정상 상태로 바꾸지 않는다.
- 보관 중 단말기를 탈거한 장비는 예기치 않은 통신 장애와 다른 상태로 설명한다.
- **보완 원칙:** 알림 상세에 관련 없는 서류 승인·장비 배정 폼을 함께 열지 않는다. 정비 배정·종결 권한은 별도 업무 설계다.

### 공통 진입·표현

- 진입 제목은 ‘보유 CPB의 현황을 한눈에’, 대상은 ‘소유주 전용 데모’, 주 버튼은 ‘데모 시작하기’로 한다. 장비·현장은 시연용임을 표시한다.
- 단일 버튼에서 소유주 운영 현황으로 시작한다. 역할 카드·내부 계정 ID를 제시하지 않는다. 문서용 [진입 시안](../design/proposals/owner-demo-2026-09-11/01-owner-entry.png)을 교체안으로 사용한다.
- PC 메뉴: 운영 현황 / 보유 장비 / 알림 / 서류. 모바일은 같은 4개 하단 메뉴를 제안한다.
- 로그인 화면과 파일 미리보기·알림 상세 패널은 공통 진입/보조 상태다. 핵심 화면 6개와 별도로 중복 집계하지 않는다.
- 공장 보관, 단말기 미장착, 실제 통신 장애, 계측 미연동은 서로 다른 뜻으로 표시한다. 최종 데이터 모델과 알림 억제 정책은 후속 설계에서 정한다.
- 정상·이상은 글자와 아이콘으로 구분하고, 마지막 수신 시각과 시연 데이터 표시를 유지한다.
- 계약 체결·투입 승인·운전자 배치·비용 정산·프로토콜 관리는 이번 6개 화면의 필수 메뉴에 추가하지 않는다. 설치 일정·계약 기간 조회는 상세에 포함한다.

## 5. 제안한 화면 구성 평가

|---|---|---|
| V5 기능 대응 | 적절 | 위치·일정·계약·담당자·영상·서류·오류·점검을 6개 화면에 연결 |
| 화면 간 중복 | 조정 후 적절 | 현황은 요약·우선순위, 목록은 전체 검색, 상세는 선택 장비 정보로 역할 분리 |

## 7. 데모 장면과 검토 항목

### 제안 시연 흐름 — 약 5분

공통 진입 장에서 ‘소유주 전용 데모’임을 확인하고 ‘데모 시작하기’를 누른다. 발표자가 역할과 계정 ID를 설명할 필요가 없어야 한다.

1. 운영 현황에서 보유·투입·보관 분포를 확인한다.
2. 장비 목록에서 현장 또는 호기로 찾고, 상세의 설치 일정·계약 기간·담당자를 확인한다.
3. 전압/3상 연결 이상 알림을 선택해 해당 호기의 상태와 발생 시각을 확인한다.
4. 같은 호기의 타설 또는 설치 영상을 열고 저장 구간 예시를 재생한다.
5. 같은 호기의 제작증·비파괴 검사 성적서를 열람한다.
6. 보관 중 단말기를 탈거한 장비를 열어 실제 통신 장애 장비와 표시가 다름을 확인한다.

### 시연 데이터 제안

| 장면 | 필요한 샘플 | 보여줄 차이 |
|---|---|---|
| 정상 운영 | 투입 중, 정상 수신, 타설 또는 설치 영상 | 정상 상태와 담당 현장 |
| 고장 확인 | 전압 또는 3상 연결 이상 | 알림 → 상태 → 영상 |
| 점검 시점 | 수송관 또는 필터 점검 필요 | 적용 기준과 누적 사용량/시간 |
| 보관 | 공장 보관·단말기 미장착 | 통신 장애와 구분 |
| 통신 장애 | 투입 장비의 예상치 못한 수신 중단 | 마지막 위치·값·수신 시각 |
| 서류 | 열 수 있는 샘플 PDF/이미지, 서류 없음 | 메타데이터뿐 아니라 파일 본문 확인 |

안전 감지 알림과 바디캠은 원문에 포함된 기능이므로 화면에 대응 위치를 마련한다. 실제 서버 수신·웨어러블 연동이 없는 경우 샘플임을 분명히 표시한다. 고객의 문구·업무 확인과 실장비 연동 검증을 혼동하지 않는다.

### 구현 후 검토 기준 제안

- [ ] 소유주 진입점에서 4개 메뉴와 6개 화면을 끊김 없이 탐색한다.
- [ ] 숫자·목록·지도는 같은 소유주와 같은 샘플 데이터 범위를 사용한다.
- [ ] 정상·보관·이상 장비를 검색하고 같은 호기의 상세·영상·서류로 이동한다.
- [ ] 1280·1024·390px에서 내용과 액션이 접근 가능하고 상세가 숨겨져 사라지지 않는다.
- [ ] V5의 영상 용도, 가동 1일분 저장 예시, 시연용 영상 표시가 일치한다.
- [ ] 제작증·검사 성적서의 본문을 열고 닫을 수 있다. 첨부 시연은 성공·실패를 구분한다.
- [ ] 알림에서 열린 대상과 후속 액션의 대상 호기가 일치한다.
- [ ] 보관·단말기 미장착, 수신 장애, 미연동을 구분한다.
- [ ] 이동 중 샘플 시각과 필터를 보존한다.
- [ ] 다른 소유주의 장비·문서·카메라 직접 주소 접근을 검사한다. 현재 한 소유주 시드만으로는 입증되지 않는다.

## 8. 후속 구현 순서

1. **데모 범위 정리:** 6개 화면·4개 메뉴와 샘플 데이터 범위를 정한다. 파일 등록자, 보존 1일의 의미, 단말기 탈부착 기록 주체 등 미결 사항은 기존 결정 원장과 연결한다.
2. **정식 명세:** 구현에 들어갈 때 신규 목록·상세의 SSOT 등록 필요 여부를 판단하고 `/ssot`·`/spec` 절차로 화면·상태·수용 기준·작업을 등록한다. 이 문서의 번호를 정식 화면 ID처럼 사용하지 않는다.
3. **핵심 과제:** PC/휴대폰에서 전체 장비 검색 → 계약·담당자 확인을 연결하고, 현재/마지막 수신 정보와 보관·미장착 상태를 구분한다. 같은 호기의 장비 서류 원문 열람을 우선 성립시킨다.
4. **데모 구성:** 단일 소유주 진입·운영 요약을 정돈하고 영상·알림을 같은 호기로 연결한다. [디자인 리뷰의 순서·판정 기준](../design/OWNER-DEMO-DESIGN-REVIEW-2026-09-11.md)에 따라 첫 화면·KPI·텍스트를 조정한다. 진입 교체는 고객 공개 전 필수 조건이다.
5. **검증:** 화면별 기능 검사, 샘플 간 정합, 각 폭의 캡처·접근성, 소유주 스코프, 게이트와 reviewer 검토 후 고객 공개 여부를 판단한다.
