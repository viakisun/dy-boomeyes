## 1. 검토 방법과 페르소나

사용자 요청에 따라 별도 AI 검토자가 **CPB 보유·임대 회사의 소유주 1명**을 가정해 의견을 냈다. [진입 시안](proposals/owner-demo-2026-09-11/01-owner-entry.png)·[운영 요약 시안](proposals/owner-demo-2026-09-11/02-owner-summary.png), 현재 앱의 현황·서류·영상 캡처를 직접 보고, [화면 정의서](../plans/owner-demo-screen-review.md)와 [디자인 개선안](OWNER-DEMO-DESIGN-REVIEW-2026-09-11.md)을 검토했다.

이하 인용문은 모두 **합성 페르소나의 가상 발언**이다. 실제 고객에게 연락하거나 인터뷰하지 않았고, 검토자가 앱을 클릭해 과제를 수행한 것도 아니다. 의견 수렴·승인·사용성 검증이 끝났다는 근거로 사용하지 않는다.

| 항목 | 설정과 근거 |
|---|---|
| 역할 | DY CPB 여러 대를 보유하고 건설현장에 임대하는 회사의 소유주. 별도의 운영 담당자 페르소나를 추가하지 않음 |
| 관심사 | 장비 위치·설치 일정·계약 기간·담당자, 이상 상황 파악, 장비 서류 대응, 추가 임대 기회 |
| 고객 자료 | V5 `관제기능` D4:D5·H35·H36·H71·M39 등. 원본을 직접 대조했던 화면 정의서의 셀 기록을 제공함 |
| 검토 가정 | 사무실 PC와 이동 중 폰에서 확인. 현장 문의를 받고 특정 호기를 찾는 상황. 실제 사용 빈도·우선순위는 미확인 |
| 설정하지 않은 정보 | 나이·성별·디지털 숙련도·확정 보유 대수·인터뷰 이력. V5의 100대/120대 사례는 실제 회사 데이터로 사용하지 않음 |

## 2. 한 문장 의견

> “화면은 전보다 읽기 편해졌지만, 제 장비가 어디에 있고 계약이 언제까지이며 누구에게 확인해야 하는지 찾는 일이 영상보다 앞에 와야겠습니다.”

이는 상황에 따라 계약·담당자를 먼저 찾는다는 가설이다. 모든 소유주가 영상을 덜 중요하게 여긴다는 결론은 아니다.

| 장비 서류 | “안전관리자가 3호기 제작증을 달라고 하면 그 파일부터 찾아야죠. 평균 완비율 57%보다 필요한 서류가 있고, 원문이 제대로 열리는지가 중요합니다.” | 호기별 제작증·검사 성적서 검색과 원문 열람 우선. 실제 파일 전달·공유 기능은 별도 확인 |

장비 목록과 전체 호기 상세는 **제안 설계**에 대한 반응이다. 운영 요약 시안도 대시보드 일부여서 전체 지도 배치가 검증된 것은 아니다.

## 4. 기존 개선안에 대한 이견과 반영 판단

| 기존 제안 | 모의 검토의 이견 | 처리 |
|---|---|---|
| 호기 상세의 주 행동은 항상 영상 보기 | 계약·담당자·서류를 찾으러 들어오는 경우도 있음 | **문서 수정.** 공통 요약에 계약·담당자를 올리고 상태·영상·서류 접근을 명확하게 한다. 진입 링크는 필요한 부분으로 안내하되 상세 배치를 매번 뒤집지는 않음 |
| 첫 화면 지도 약 2/3 | 현장 이름으로 장비를 찾는 상황에는 검색·목록이 더 빠를 수 있음 | **조건부 채택.** 비율은 고정 기준에서 제외. 검색·전체 목록 접근을 첫 화면에 두고 지도와 목록의 사용 우선순위는 실제 고객에게 확인 |
| 우선 알림 3건 표시 | 나머지가 몇 개인지 모르면 문제가 세 건뿐이라고 생각할 수 있음 | **문서 수정.** 전체 영향 장비 수·현재 표시 수·전체 보기 함께 제시. 표시 건수와 우선순위는 별도 규칙으로 정함 |
| 고객용 진입 교체부터 구현 | 진입이 좋아도 폰에서 상세와 파일이 열리지 않으면 체험할 수 없음 | **순서 수정.** 장비 찾기→상세, 정보 시각, 서류 원문을 먼저 성립시킴. 진입 교체는 고객에게 제시하기 전 필수 조건으로 유지 |
| 진입 미리보기는 이상/수신 중단/미장착 3대 | 평상시 장비 운영과 계약 확인의 가치가 약함 | **다음 시안 수정 항목.** 정상 장비·계약 정보를 포함. 현재 PNG는 v2 정적 시안으로 보존하며 수정 완료로 표시하지 않음 |

모의 의견을 실제 고객의 요구 확정으로 승격하지 않는다. 이번에 반영한 것은 되돌릴 수 있는 **문서의 구성·우선순위**이며, 제품 코드·정식 명세·SSOT의 변경이 아니다.

## 5. 소유주 관점의 우선순위

1. **전체 장비 찾기 → 계약·담당자 확인을 PC와 폰에서 연결한다.** 정상 장비와 보관 장비도 찾고, 상세에서 선택 호기를 유지한다.
2. **현재 정보와 마지막으로 받은 정보를 구분한다.** 수신 중단·보관·단말기 미장착을 구분하고 위치·측정값·영상에 해당 시각을 붙인다.
3. **같은 호기의 제작증·검사 성적서 원문을 연다.** 문서를 닫아도 이전 장비와 목록 위치로 돌아간다.

그 뒤 단일 데모 진입, 첫 화면 요약, 영상·알림 이동, 글자·여백을 같은 흐름 안에서 다듬는다. 진입 화면의 교체 필요성은 유지하되 내부 구현 순서와 고객이 보는 화면 순서를 구분한다.

시간 배분은 시연 제안이며 실제 수행 시간·성공률이 아니다. 관련 영상이 없는 알림은 영상 없음으로 표시하고 상태 확인 흐름을 유지한다.

## 6. 근거의 경계와 실제 고객 확인 질문

| 구분 | 내용 |
|---|---|
| V5에 직접 있음 | CPB 회사용(M39), 운영 편의·추가 일거리(D4:D5), 위치(H35), 설치·계약·담당자(I9:N25/H71), 장비 서류(H36), 보관·단말기 탈부착(H56:H57), 타설·설치 실시간(H48:H49), 안전 감지 실시간 제외(H50), 가동 1일분 저장(H55) |
| 이번 모의 검토 가설 | 현장 문의 시 검색 우선, 계약·담당자를 영상보다 먼저 찾는 상황, 계약 종료일 순 조회 선호, 지도 비율·알림 표시 건수·진입 미리보기의 적절성 |
| 확인이 필요한 기능·규칙 | 실제 임대 가용 판정·반출 가능일, 자동 재배치·승인, 전화 연결·서류 발송·영상 공유, 서류 세부 권한, 보관·탈부착 기록 주체, 영상 보존·삭제 정책 |

내부 [요구 원천](../../ssot/requirements.yaml)의 FR-025는 가용 현황의 제안 범위다. FR-043은 보관·단말기 탈부착의 미착수 제안 요구이며, 관련 [결정 원장](../../ssot/decisions.yaml)의 DISC-059는 open이다. **공장 보관 ≠ 즉시 임대 가능**, **계약 종료일 ≠ 실제 반출일**을 유지한다.

실제 고객 검토에서는 아래 질문을 사용한다. 이번 문서에 답변을 받은 것으로 기록하지 않는다.

- 최근 장비 현황을 확인했던 상황에서 무엇을 가장 먼저 찾았는가?
- 장비를 찾을 때 호기 번호·현장명·건설사 중 어떤 이름을 주로 사용하는가?
- 새 임대 문의가 오면 계약 종료일 외에 무엇을 확인해야 장비를 보낼 수 있는가?
- 이상 연락을 받으면 누구에게 어떤 정보를 확인하며, 화면에 무엇이 있어야 전화 전에 판단할 수 있는가?
- 제작증·검사 성적서는 누가 등록하고, 요청한 상대에게 어떤 방법으로 전달하는가?
