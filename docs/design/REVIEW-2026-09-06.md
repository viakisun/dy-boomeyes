# 디자인 리뷰 — 2026-09-06 (wave ≤ 2 화면 41 · 캡처 97장)

기준: "전문적 · 직관적 · 간결". 대상은 W2 종료 시점의 실화면 41(웹 20 · PWA 21), 캡처 `shots/`(라이트 56 · 다크 41)와 코드. 판정은 화면을 눈으로 본 것과 `pnpm design:audit`(UI 문자열의 내부 식별자 검출 — 마크업 리터럴만 세고 `<script>` 값이 `{expr}`로 보간되는 경우(로그인 카드 eyebrow · 브레드크럼 표면 코드 · 푸터 wave 숫자)는 세지 않는다, D7에서 보완) 수치로 뒷받침한다.

**결론 한 줄.** 토큰·컴포넌트·셸(구조)은 서 있다. 간결함을 깨는 것은 구조가 아니라 **잡음**(내부 식별자·설명문 부제·미완성 아이콘 자리)과 **골격 편차**(헤더 3종 · 표 행 높이 불규칙 · 전폭 폼 · 색 숫자 Stat)다. 열넷 중 열하나는 규칙과 공용 컴포넌트로 잡히고, 셋은 화면 설계 판단이다.

## 3. 잘 된 것(유지)

- 상태 표현: 점 + pill + 텍스트 병행(StatusPill), 도메인 색(장비·업무·서류) 일관 — QA 패리티의 기둥.
- 목록 → 인스펙터(Linear) 흐름이 웹 9화면에서 같다. 인스펙터 안 KeyValueList · Timeline도 같은 모양.
- PWA 카드 규칙(패딩 20 · 배지→제목 8 · 제목→설명 2)과 전폭 CTA 48 — Crane Eyes에서 취한 것이 그대로 산다.
- 카메라 월·쇼케이스의 다크 강제, 지도 마커 팬, 배너·토스트·시트 — 도메인 컴포넌트가 화면마다 다시 그려지지 않았다.
- 접근성: axe serious 0(41화면) · 대비 게이트 · 키보드 행 포커스.
