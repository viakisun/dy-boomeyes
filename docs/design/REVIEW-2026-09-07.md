# 화면 검수 — 2026-09-07 (구현 화면 41 전수 · 근본 원인 분류)

사용자가 갤러리·로컬 데모를 직접 보고 화면 결함을 지적하며 "코드 문제인지 디자인 시스템 문제인지" 근본 원인을 물었다. 5개 배치로 41개 화면 전수를 리뷰했다 — 기존 캡처(라이트·다크 101장)를 전부 육안으로 보고, 탭·필터·시트 등 캡처 도구가 클릭하지 않는 진입 상태를 로컬 preview에서 직접 열어 추가로 확인했으며, 발견마다 관련 컴포넌트·라우트 소스를 읽어 원인을 확정했다. 이 문서의 모든 발견은 이 세션에서 파일:줄까지 직접 읽어 재확인한 것이다(하위 리뷰 에이전트 보고를 그대로 인용하지 않았다).

**결론 한 줄.** 화면마다 제각각인 실수가 아니라, **공유 컴포넌트 5개(`Stat` · `StatusPill` · `Switch` · `ChecklistForm` · `Button`)의 결함 하나하나가 화면 여러 개에 동시에 나타난 것**이 결함의 대다수를 설명한다. 나머지는 반복되는 코드 패턴(쿼리 전환)과 화면별 개별 실수다. 디자인 시스템(토큰·규칙) 자체는 옳다 — 이번에 찾은 결함 중 토큰 값이나 디자인 규칙이 틀린 경우는 없었다.

## 6. 커버리지

5개 배치, 웹 19 + PWA 22 = **41개 화면 전수**(웨이브 ≤ 2, 웨이브 4 자리 화면 12개는 범위 밖). 기존 캡처 101장 전부 육안 확인 + 탭·필터·시트 등 클릭 진입 상태를 로컬 preview에서 추가로 열어 확인(반려 사유 시트 등 지금까지 한 번도 캡처된 적 없던 화면 포함). 근본 원인 클러스터 8건(F-15~F-22), 그중 4건이 화면 2개 이상에 동시 영향. 화면별 개별 결함 12건. 코드는 수정하지 않았다 — 순수 조사·분류 문서다.

## 8. 수정 라운드 갱신 (2026-09-07~08 — F-15~F-22 수정 진행 중 발견)

- **F-18 재분류: 결함 아님.** 수정 착수 전 재확인한 결과, `packages/tokens/dist/DY-design.md` §0-4가 "색 배경 pill은 warning·danger에만 … 그 밖의 상태는 텍스트 라벨로(**StatusPill quiet · Badge subtle은 중립**)"이라고 명시한다 — quiet 분기의 `text-fg`(중립색)는 오타·누락이 아니라 스펙이 요구하는 정확한 구현이다. `TONE[tone].fg`가 정의돼 있는데 quiet 분기에서 안 쓰는 것은 사실이지만, 그건 quiet가 애초에 그 값을 쓰면 안 되기 때문이다. 코드 수정 없음 — §2의 F-18 행은 재검토 기록으로 남기고 §4 백로그 1번의 "F-18" 언급은 무효로 처리한다.
- **F-22 수정 완료(PR #44, `packages/ui/src/primitives/Button.svelte`).** `disabled:opacity-40` 제거, 톤 무관 공통 중립 톤(`fg.muted`×`bg.surface-sunken`/`canvas`/`surface`, 기존 PAIRS 재사용)으로 교체 — 실측 대비 2.36~2.56:1 → 5.42:1. §4 백로그 6번의 "컴포넌트" 절반은 완료, "게이트에 합성 대비 케이스 추가"는 미착수로 남음.
- **F-22 수정 중 새로 발견 — disabled→enabled 전환 중 일시적 저대비(별도 후속 필요, 아래 9번으로 백로그 추가).** 정적 상태 대비는 해결됐지만, `transition-colors`가 배경·글자색을 동시에 보간하는 동안 두 끝점은 각각 대비를 만족해도 중간 프레임의 대비가 순간 무너지는 경우가 있다 — A2-01 로그인 "입장" 버튼(사용자 목록 비동기 로드로 잠깐 비활성인 버튼)에서 axe로 재현(최저 1.02:1), 간헐적(부하·타이밍 의존, 격리 재현율 약 1/5~1/4). `enabled:transition-colors`로 막아 봤으나 CSS transition은 도착 상태 기준으로 적용 여부가 결정돼 disabled→enabled 방향엔 효과가 없어 원복 — hover/active 전환은 유지한 채 disabled 경계만 스냅시키려면 컴포넌트 상태 전환 구조 자체를 다시 설계해야 한다.

§4 백로그 추가:

9. Button의 disabled↔enabled 전환 중 일시적 색상 대비 저하(위 참고) — hover/active 전환과 분리해 disabled 경계는 스냅시키는 구조 설계, 또는 상태 전환 애니메이션 자체의 대비 안전성을 검증하는 방법(예: 전환 중간 프레임 샘플링 테스트) 도입.
