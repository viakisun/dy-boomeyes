# ADR-014 — 디자인 언어 전환 (Accepted 2026-09-12 — 사용자 결정)

## 맥락
사용자가 Claude Design에서 소유주 앱 전체를 다시 그렸다(`운영 현황 목업.html` · 기획 문서 3편, «확정 2026-09-12»). 시안은 재도색이 아니라 정보 구조와 색·타이포 언어를 함께 바꾼다. 사용자 지시는 **"시안을 새 기준으로 · 토큰은 전면 전환"**이었다.

시안이 정한 값을 측정한 결과:

| 축 | 시안 | 현행 |
|---|---|---|
| accent | `#075A60` OKLCH L .427 C .071 **H 203** | navy `#0d2877` L .317 C .139 H 265 |
| 바탕·글자 | bg `#F4F6F8` C .003 · ink `#172D39` C .036 · ink2 `#40616E` C **.044** — **H 225~248** | 균일 C .008(회색) |
| 고정폭 | IBM Plex Mono(Google Fonts) | JetBrains Mono 선언만 — 저장소에 `@font-face` 0건이라 실제로는 시스템 폰트 |
| 정상 | 초록 **텍스트·얇은 테두리·요약 점**(`#1F7A4D`) · 지도 마커는 잉크색 | 색 없는 중립 라벨(원칙 4) |
| 상태 면 | 채운 배경 pill 없음 — 전부 색 글자 | warning·danger는 채운 pill |

## 결정

**1. accent 앵커 = `#005679`(OKLCH L .428 C .090 H 234.7).** 시안 값을 그대로 쓰지 않고 파랑 쪽으로 32° 돌린다.

시안의 `#075A60`(H 203)은 `progress`(teal.9 `#007369`, H 184)와 OKLab ΔE **.079**로 가깝다. 대비비는 이 판단에 쓸 수 없다 — 명도만 재므로 색조를 돌려도 1.38 → 1.44로 거의 움직이지 않는다. H를 5° 단위로 훑어 `teal`과 `info`(blue.9) **양쪽과의 최소 거리**를 최대화하는 지점을 찾았다:

| H | hex | ΔE vs teal | ΔE vs blue | min |
|---|---|---|---|---|
| 203(시안) | `#005b5f` | .079 | .232 | .079 |
| 225 | `#005870` | .092 | .202 | .092 |
| **235** | **`#005679`** | **.104** | **.185** | **.104** |
| 245 | `#005385` | .123 | .164 | .123 |
| 265 | `#344c85` | .142 | .163 | .142 |

min은 H와 함께 계속 오르지만 H 245를 넘으면 binding 제약이 teal에서 **info 파랑**으로 넘어가고, H 265에서는 사실상 현행 navy로 되돌아가 시안의 인상을 버린다. H 235는 teal 거리를 시안 대비 32% 벌리면서 시안의 깊은 청록빛을 유지하는 지점이다. 시안의 **중립색이 이미 H 225~248**이라 accent를 이 대역에 두면 중립과 같은 색조 가족이 된다.

**2. 중립 램프에 색조 곡선을 넣는다.** 균일 채도는 회색으로 읽혀 accent와 같은 가족으로 보이지 않는다. `ramps.mjs`에 `NEUTRAL_C` 비율을 두어 바탕은 거의 무채, 글자·테두리로 갈수록 색조를 띠게 한다. 시안 값과 대조:

| 단계 | 쓰임 | 우리 | 시안 |
|---|---|---|---|
| 2 | canvas | `#f8fafc` C .003 | `#F4F6F8` C .003 |
| 5 | border-subtle | `#dde4e8` C .009 | `#DDE3E8` C .009 |
| 10 | fg-subtle | `#647884` C .030 | `#7A909B` C .030 |
| 11 | fg-muted | `#4a6879` C .044 | `#40616E` C .044 |
| 12 | fg-default | `#071d29` C .036 | `#172D39` C .036 |

채도는 모든 대응 단계에서 일치한다. 명도 사다리(`NEUTRAL_L`)는 우리 것을 유지한다 — 시안보다 양 끝이 넓어 대비 여유가 크다. 다크는 시안에 없으므로 같은 곡선에서 파생한다.

**3. 정상(success) 초록을 색 예산에 넣는다 — 원칙 4 개정.** 글자·얇은 테두리·요약 칩의 작은 점에만 쓰고 면은 채우지 않는다. 화면당 색상 계열 한도는 3 → **4**. `color-audit.mjs`의 예외 목록(`A2-04` `B1-07` `B4-05`, TelemetryGauge 초록 때문에 4계열이었고 «사용자 결정 대기»로 남아 있던 것)을 없앤다.

측정 결과 **새 초록이 필요하지 않았다** — 우리 `green.9`(`#067831`)와 시안의 `#1F7A4D`는 ΔE **.038**(같은 색), 대비는 5.37 대 4.91로 우리가 더 안전하다. 시안의 다른 상태색도 램프 안에 이미 있다: `fault` ΔE .053(red.9) · `store` ΔE .044(neutral.9) · `late` ΔE .091(yellow.11) · `check` ΔE .028(**yellow.8**). 시안이 앰버를 점검·지연 두 단계로 나눈 것은 새 색조가 아니라 **같은 램프의 다른 단계**다.

**4. 지도 마커의 정상은 중립으로 둔다.** 시안 지도를 열어 보면 정상 마커는 `--ink`(짙은 슬레이트)이고 초록은 목록·표의 글자와 요약 점에만 나온다. 이상만 색을 갖는 «무게 = 심각도» 문법은 시안과 우리가 같다.

**5. IBM Plex Mono 라틴 서브셋을 앱이 자체 배송한다.** `apps/*/static/fonts/*.woff2`(각 10KB) + `app.css`의 `@font-face`. Google Fonts 링크를 쓰지 않는다 — PWA는 오프라인에서 같은 글꼴로 떠야 하고, 서비스 워커가 `static/`을 이미 선캐시한다. 한글 sans 스택은 **바꾸지 않는다**: 시안의 Noto Sans KR은 디자인 도구가 Google Fonts만 제공해서 고른 값이고, 한글 웹폰트는 서브셋 배송이 별개 과제이며 전 역할 캡처 기준선이 시스템 폰트로 잡혀 있다.

**6. 사용하지 않는 `sys.color.domain.map.*` 16토큰을 없앤다**(사용처 0건 · 지도는 `equipment` 매핑을 쓴다). 토큰 608 · 도메인 매핑 96.

## 근거
- **왜 시안 값을 그대로 쓰지 않는가** — 시안은 한 화면을 그렸고 우리 램프는 6역할 전 화면을 덮는다. `progress` teal은 시안에 없는 상태(정비·진행)라 시안이 충돌을 볼 수 없었다.
- **왜 대비비가 아니라 ΔE인가** — 대비비는 상대 휘도 하나만 본다. 색조가 다른 두 색이 같은 명도면 21:1 체계에서 구분되지 않는다. OKLab ΔE는 명도·채도·색조를 함께 재고, ~.05가 «분명히 다른 색»의 실용 경계다.
- **화면 코드는 한 줄도 바뀌지 않는다** — 49파일 129 사용처가 모두 `sys`/`cmp` 유틸리티를 거친다(ADR-004). 앵커 두 줄과 램프 한 줄이 전체를 옮긴다.

## 결과
- 되돌리기: `brands/DY.json`·`ref/color.config.json`의 앵커와 `ramps.mjs`의 `NEUTRAL_C`를 되돌리면 원래 팔레트로 돌아간다. 캡처 기준선(`shots/`)은 다시 승인해야 한다.
- 수기 동기 대상: `apps/pwa/src/app.html` `theme-color` · `manifest.webmanifest` `theme_color`/`background_color` · `tests/e2e/pwa-install.spec.ts` 기대값 · `tools/docs-gen/assemble.py` 문서 CSS · `pnpm brand:build` 산출물. `docs/QA.md`가 이 목록을 갖는다.
- **계기 막대는 정상일 때 중립으로 채운다** — `TelemetryGauge`가 정상 구간을 `bg-success`로 채우고 있었다(리뷰 지적). 색은 «주의가 필요하다»는 뜻이므로 정상까지 채색하면 색이 계기 눈금이 된다. 시안의 소모품 막대도 `--ink2`로 채우고 한계 근처에서만 앰버로 바뀐다. 개정된 원칙 4(«정상은 배경 없이»)와 맞추어 `bg-neutral`로 바꿨다.
- 남은 것: 한글 웹폰트 배송 · 시안의 «면을 채우지 않는» 상태 문법을 warning·danger까지 확장할지(소유주 화면은 §11.8이 이미 글자 우선).
