# ADR-013 — 타설량 시계열 모델: 서버 집계 시간 버킷 (Proposed 2026-09-11 — 계획 승인 2026-09-10, 사용자 확인 대기)

## 맥락
DY 연구개발2팀 자료(기술경진대회)는 수송관 진동 센서 S1·S2의 통과 시간 Δt로 유속 v=L/Δt, 순간 토출량 Q=v×A, 누적 Σ(Q×Δt)를 산출한다. 산출 주체(CPB 제어부 vs 서버)·올리는 값과 주기·규격별 단면적·리셋 절차는 DISC-055로 열려 있다. 현행 SSOT는 누적 타설량을 부품 점검 보조지표로만 둔다(FR-032·DISC-038). 화면(B1-02·A1-05·A2-04·B4-07)은 시간당 추세·가동률·누적을 요구한다(FR-039).

## 결정
1. 관제가 다루는 타설량의 단위는 **서버 집계 시간 버킷**(`PourSeries.buckets[] = {at, m3}`, 1시간)이다. 원시 타수·Δt·순간 유속은 관제 도메인에 싣지 않는다.
2. 산출 상수(D125 단면적 0.0123 m²·센서 간 거리 L·버킷 길이·작업 시간대)는 `packages/domain/src/pour.ts` 1곳에 둔다. 화면은 `PourSeries.basis`로 근거를 보여주되 숫자를 갖지 않는다.
3. **가동률 = 작업 시간대(KST 07~17시) 버킷 중 타설 버킷 비율**. 야간 0은 분모에 넣지 않는다.
4. `Device.pour`는 선택 필드 — 없으면 "미연동"(FR-034와 같은 축). 전부 0인 시계열은 "가동 0"이지 미연동이 아니다.
5. 버킷 경계는 UTC ms 산술만(`Math.floor(t/H)*H`). KST 오프셋이 정수 시간이라 KST 정시와 같다.

## 근거
- DISC-055의 어느 결론(제어부 산출 / 서버 산출, 주기 1분 / 1시간)에서도 관제 화면이 읽는 형태는 시간 버킷이다 — 원시값을 실으면 결론마다 타입이 바뀐다.
- 시드는 리터럴 24버킷이라 `Math.random` 0, 캡처 결정성은 단위 테스트(`pour.test.ts` 첫/마지막 `at` 리터럴)가 픽셀 diff보다 먼저 지킨다.
- `Part.pouredM3`(부품별 보조지표)와 `PourSeries.cumulativeM3`(장비 센서 리셋 이후 누적)는 다른 축이므로 합치지 않는다.

## 결과
- 되돌리기: 원시값이 필요해지면 `PourSeries`에 `raw?` 축을 더한다(가산). 버킷 길이는 `basis.bucketMs`로 화면이 읽으므로 상수만 바꾼다.
- 후속: DISC-055 확정 시 `pour.ts` 상수 갱신 · 규격별 단면적 표 · 리셋 이벤트(수송관 교체) 반영.
