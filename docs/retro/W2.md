## 2. 잘 된 것
- **탐색 → 스크립트 → 워크트리 드라이런 → 게이트 → 캡처 육안 → PR → 리뷰 루프**: 브랜치마다 Explore 에이전트가 앵커 원문을 모으고, 편집은 `str.replace` + assert 스크립트로 적용해 실패가 조용히 지나가지 않았다. 드라이런은 `git worktree add --detach`로 본 트리를 건드리지 않았다.
- **병렬 운영**: 리뷰·CI를 기다리는 동안 다음 브랜치 탐색을 돌려 대기 시간이 거의 없었다. 리뷰어의 "머지 불가"(B3)와 비차단 권고는 다음 브랜치 설계에 바로 반영됐다(현장 차원 완비율 · 픽스처 docnew · 쿼리 값 비교).
- **정직한 자리+**: 부품·복기 5화면은 상태기계 실소비·시드·이력까지 만들고 스캔·발주·실영상 동기는 비활성 표기(DISC-038/043/044)로 남겼다. 리뷰어가 "우회인지" 판단하도록 명시적으로 물었고, 설계 메모에 한계를 적었다.

## 3. 사고 (CLAUDE.md 사고 SOP 5건 추가)
토스트 `.first()` 단언(B5) · 쿼리 전환이 `?state=&capture=`를 버려 픽스처 소실(B8) · 감싸는 `<label>`의 접근 가능한 이름 + 비동기 액션 중 `$derived` 뒤집힘(B9) · ISO 슬라이스 UTC 표시(B9) · 자리 화면을 세는 게이트 부재 + 리뷰 에이전트 stall(B10·B15).
공통 패턴: 게이트가 녹색이어도 **캡처를 눈으로 보지 않으면** 잘못된 것(UTC 시각 · 버튼 넘침 · 라벨 겹침)이 남는다 — "캡처 N장 OK"는 파일 존재만 뜻한다(W0 SOP 재확인).
