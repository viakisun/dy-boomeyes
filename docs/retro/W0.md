## 2. 잘 된 것

- **리뷰 루프**: reviewer 에이전트 판정 → 차단 해소 → merge. 브랜치 8개 중 첫 판정 "머지 가능"은 1개(마지막 수정 브랜치)였고, 매번 1~4건의 실제 결함(미구현 AC · 잠금 파일 · 정규식 오타 · 데이터 유실 · 비반응 배너 · 단위 검증 누락 · 딥링크 프로파일 우회)을 잡았다. 게이트가 녹색이어도 스펙 리터럴 요건은 리뷰가 잡는다.
- **캡처 = 완료 증거**: 빈 지도 캡처를 "OK"로 세던 것을 실패로 바꾸고, 셸까지 렌더하게 한 뒤부터 캡처가 리뷰·데모 근거가 됐다.
- **SSOT 근거 강제**: 스펙 AC를 ssot(FR·상태·데모 장면·ACC)에서 도출하게 하자 리뷰가 "근거 없음"을 지적할 수 있었다(A2-04 오기 · C-104 스코프 · P-NVR 소스).

## 3. 사고 (CLAUDE.md 사고 SOP 11건)

지도 캡처 빈 화면 · 숫자 스케일(gap-1 = 1px) · fg-subtle 대비 · 게이트 우회(`;` 체인) · 리뷰 전 머지 · Turbo 캐시 · 고아 preview 서버 · API 경계 참조 공유 · `$state` 프록시 · 정규식 치환의 백스페이스 · 기본 픽스처가 live에 적용.

공통 패턴: **"녹색인데 틀림"** — 도구가 검사하지 않는 곳(정규식이 죽은 lint, 캐시된 번들, 셸 없는 캡처)에서 조용히 실패했다. 대응은 전부 "검사에 프로브를 넣는다"였다(lint 규칙 생존 프로브 · 지도 픽셀 표준편차 · 캐시 off · 리스너 확인).

## 4. 방법론 v1.1 반영 (METHOD.md §11)

1. **머지 조건에 리뷰어 판정 인용 명시** — verify 녹색 + "머지 가능" 인용 둘 다 없으면 merge 금지(1회 위반).
2. **명령 체인은 `&&`** — 게이트 실패 시 커밋이 되지 않게(CLAUDE.md 검증 명령 절).
3. **픽스처는 capture·e2e 전용** — 실사용 흐름은 순수 시드(QA §3).
4. **API 경계 규칙** — 반환은 복사본, 인자는 `$state.snapshot`(ADR-002 Rules).
5. **캡처 규약 확장** — 셸 렌더(세션 합성) · TZ 고정 · fullPage 금지 · PWA 문서 높이 · 지도 idle 실패 집계(QA §3, 반영됨).
6. **디자인 토큰 lint 범위** — 숫자 스케일 · 초기화된 기본 스케일 · style 블록 px까지. 남은 빈틈(border-N · ring-N · duration-N · max-w-*)은 W1 항목.
7. **리뷰어 근거 형식** — file:line + 게이트 인용(reviewer.md, 잘 지켜짐).
