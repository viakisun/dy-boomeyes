## 2. 잘 된 것

- **가이드 → 측정 → 브랜치**: D0에서 §11 골격·§12 카피를 먼저 문서로 고정하고 `design:audit`로 수치(64건)를 만든 뒤 D1~D7이 그 수치를 0으로 내리는 구조였다. 리뷰어는 매번 가이드 조항을 인용해 대조했다(예: §10-2 탭 라벨 · §11.1 뒤로 가기 · §12.1-2 식별자).
- **근거를 화면 밖으로**: `data-ref`/`ref` prop + 시연 바 "근거" 토글이 "추적성은 코드·문서의 일"이라는 원칙을 실제로 지켰다. 검토자는 `?scene=`에서 토글로 근거를 보고, 사용자는 ID를 보지 않는다.
- **체인 브랜치 병렬 운영**: D2~D7을 앞 브랜치 위에 쌓아 리뷰·CI 대기 없이 진행했고, PR base는 앞 PR 머지 시 main으로 바꿨다.

## 3. 사고 (CLAUDE.md 사고 SOP 5건 추가)

- 기준선 커밋이 브랜치 순서에 끼임 — 기준선은 main 병합 뒤에만.
- `shots/baseline`의 `manifest.json`·`MANIFEST.json` 대소문자 충돌(macOS) — 프리셋 디렉터리에는 소문자 manifest를 쓰지 않는다.
- 편집 스크립트 뒤 `;` 재발(D6) — `PYEOF` 다음 토큰은 `&&`뿐(W1 SOP를 다시 어겼다).
- 리뷰어의 stale ref 비교(D2) — base는 커밋 해시로.
- 기준선 봇 커밋의 CI가 승인 대기(D2) — PR head run이 `action_required`면 API로 승인.

공통 패턴: 게이트 체인에서 `&&`가 빠진 자리마다 "녹색인데 틀린" 상태가 생긴다(W1·W2와 같은 교훈).
